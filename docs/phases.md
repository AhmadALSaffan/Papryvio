## المرحلة 1 — الأساس والواجهة

- مشروع Tauri 2 + Rust + React + TypeScript (strict) + Vite.
- طبقات Rust: `domain` / `application` (منافذ وحالات استخدام) / `infrastructure` (SQLite، ملفات، PDF) / `desktop` (أوامر IPC وأحداث) / `bootstrap.rs` (composition root).
- SQLite عبر rusqlite (bundled، WAL، foreign_keys، busy_timeout) مع migrations مرقمة.
- عقود IPC مولدة إلى TypeScript عبر `ts-rs`، وغلاف أحداث موحد (schema_version، event_id، sequence).
- tokens التصميم، الخطوط محزمة محليًا، الشعار وأيقونات التطبيق.
- AppShell بشريط عنوان مخصص (تصغير/تكبير/إغلاق/سحب فعلية)، LibrarySidebar، حالة المكتبة الفارغة.
- المجموعات: إنشاء، إعادة تسمية، حذف، اختيار — كلها محفوظة.
- العربية/الإنجليزية مع RTL كامل، الإعدادات محفوظة.
- onboarding: الترحيب واللغة، خطوة النماذج (تأجيل صريح)، إنشاء المجموعة؛ التقدم محفوظ مع flow_version.

**معيار الإنجاز:** نافذة محلية تعمل مع قاعدة بيانات فارغة دون بيانات عرض.

## المرحلة 2 — الاستيراد والقراءة

- اختيار الملفات عبر dialog أصلي من Rust أو السحب والإفلات، مع import token بدل مسارات من الواجهة.
- تحقق من النوع الفعلي (`%PDF-`) والحجم، SHA-256، منع التكرار وربط المستند الموجود بمجموعة أخرى.
- نسخ إلى staging ثم library داخل AppData، مع recovery عند بدء التشغيل.
- عامل PDF منفصل (نفس الملف التنفيذي بمعامل `--pdf-worker`) يستخدم PDFium، بمهلة وحد لحجم المخرجات وبروتوكول أسطر JSON.
- استخراج الصفحات: النص، الأبعاد، الدوران، مقاطع النص بإحداثياتها، علامات الجودة، كشف الملفات الممسوحة (needs_ocr) والمحمية بكلمة مرور.
- metadata: العنوان/المؤلفون/السنة من PDF مع مصدرها، أو اسم الملف مؤقتًا، والتعديل اليدوي له الأولوية.
- وظائف مستمرة في قاعدة البيانات: تقدم حقيقي، pause / resume / cancel / retry، استئناف بعد إعادة التشغيل من checkpoint.
- قارئ PDF.js محلي: تنقل، إدخال رقم صفحة، تكبير، ملاءمة العرض، تحديد ونسخ النص.
- إزالة من مجموعة، حذف من المكتبة مع tombstone وحذف المشتقات والملف.
- onboarding: خطوة استيراد أول ورقة بتقدم فعلي.

**معيار الإنجاز:** إضافة PDF المستخدم وقراءته والتنقل بين صفحاته واستكمال الوظيفة بعد الإغلاق.

## المرحلة 3 — النماذج والفهرسة والبحث

- مزودون: Ollama محلي (loopback فقط)، مفتاح API (OpenAI/Anthropic/OpenRouter/GitHub Models/متوافق مع OpenAI)، تسجيل دخول ChatGPT الرسمي، وGitHub Copilot عبر Device Flow وSDK الرسمي.
- الأسرار في Windows Credential Manager، وموافقة صريحة لكل مزود سحابي قبل إرسال نصوص الأوراق.
- اختبار فعلي لكل نموذج قبل اعتماده (أبعاد التضمين، رد التوليد).
- التقسيم داخل الصفحة، FTS5 مع BM25 وتطبيع عربي، متجهات float32 مطبّعة، أجيال فهرسة ونشر ذري، إعادة التضمين عند تغيير النموذج.
- بحث بالكلمات والمعنى والهجين (RRF)، مع وصف دقيق لما بُحث فيه وما لم يُبحث.

## المرحلة 4 — السؤال والمقارنة والتسليم

- نطاق بحث صريح، EvidenceBundle محفوظ لكل محاولة، توليد بقالب مُرقّم، تحقق بنيوي من الاستشهادات والاقتباسات والأرقام، إجابة جزئية أو «لا دليل» بصدق.
- فتح الصفحة الأصلية مع تظليل أصفر من إحداثيات PDFium، التنقل بين الاستشهادات بـ [ و]، والعودة بـ Esc.
- محادثات محفوظة، إلغاء وإعادة محاولة، حفظ السؤال عند غياب النموذج.
- مقارنة ورقتين بمحاور افتراضية ومخصصة، استرجاع مستقل لكل خلية، حالات الخلية، تصدير Markdown وCSV.
- بقية onboarding (النماذج، السؤال الأول، فتح المصدر، المقارنة) تكتمل من أحداث فعلية.
- أداة تقييم `papryvio-eval` (Hit@k، Recall@k، MRR، وفحص الإجابات)، وبناء installer.
